# Telegram: рамки доступа, обработки сообщений и продвижения

Проверено 29.10.2026 по официальным документам:
- https://core.telegram.org/bots
- https://core.telegram.org/bots/features
- https://core.telegram.org/bots/api
- https://telegram.org/tos/bot-developers
- https://telegram.org/tos/content-licensing
- https://core.telegram.org/api/terms

## Возможности
- Бот создаётся через @BotFather, имеет отдельную метку «bot» и использует Bot API.
- В приватном чате обычный бот не начинает переписку первым: человек должен обратиться к нему.
- В группах после добавления бот может реагировать на команды, ответы и упоминания. Privacy Mode ограничивает входящие сообщения; администраторские права/отключение Privacy Mode расширяют доступ, но не дают разрешения на произвольный сбор или обработку.
- Guest Mode (Bot API 10.0, введён в мае 2026): бот может получить специальное обращение по упоминанию и ответить один раз без членства в чате. Нет доступа к истории или списку участников; не всякий чат поддерживает эту функцию.
- Inline Mode позволяет пользователю самостоятельно вызвать сервис в строке ввода сообщения.
- Возможны Business Bots с правами, предоставленными владельцем бизнес-аккаунта.

## Запрещённые или неподходящие для проекта подходы
- Массовое скрейпинг/индексация содержимого Telegram и создание AI-датасетов из публичных групп.
- Автоаккаунты/юзерботы для обхода ограничений Bot API или отправки рекламы без запроса.
- Персональные сообщения пользователям, которые не обращались к боту, обход ограничений/модерации, фальшивая активность и скрытая реклама.
- Сбор избыточных персональных данных, повторное использование данных одной группы в другом контексте без надлежащих прав.

## Управление согласием и данными
- Перед обработкой: явное сообщение «Я AI-ассистент [организация], обрабатываю ваши сообщения для ответа на запрос; /privacy — сведения, /delete — удалить данные, /human — человек».
- Для личных чатов реализовать отдельное активное согласие при первом контакте, если предполагается передача текста внешнему LLM. Для групп согласовать действие бота с администрацией, уведомлять участников, а при отсутствии необходимых индивидуальных согласий не передавать групповые данные во внешний AI-сервис.
- Хранить по умолчанию только служебные id диалога, время, статус обработки, факт согласия/отказа и минимальные данные, необходимые для предоставления услуги; не сохранять сырые логи чужих чатов.
- Предусмотреть отзыв согласия, ` /delete `, ограничение срока хранения, политику приватности, контроль секретов и аудит доступа. Сроки определить при проектировании с учётом юрисдикции и цели.
- Использование Telegram-контента в AI-решениях требует отдельной юридической и договорной проверки; запрет массового AI-scraping не обходится пометкой «публично».

## Поведение в группах
- Только разрешённые группы: allowlist `chat_id`; приглашение/одобрение администратора.
- По умолчанию триггеры: `@mention`, команда `/ask`, прямой reply боту или осознанный вызов Guest Mode.
- Запрещены вмешательство в каждый вопрос без обращения, агрессивное продвижение, автоматические приглашения в приват, ссылки без пользы для вопроса.
- При вопросе о товаре: коротко помочь → при необходимости предложить *одну* релевантную ссылку/каталог → завершить. Рекламный интерес и связь с брендом не скрывать.
- Команда `/quiet` для администратора, глобальный kill switch, лимиты, дедупликация, эскалация конфликтов.

## Пример прозрачного приветствия
«Привет! Я AI-помощник SYMMETLINE. Помогу разобраться с рюкзаками и сумками, а если нужен человек — передам вопрос менеджеру. Я отвечаю на обращения ко мне, не читаю всю переписку группы. Перед использованием AI-ответов ознакомьтесь с /privacy и подтвердите согласие.»

## Проверки при запуске
- [ ] Условия Telegram повторно проверены на дату выпуска.
- [ ] Admin consent/allowlist задокументированы.
- [ ] Privacy Mode включён для MVP; не запрашиваем лишние права.
- [ ] Сервис не отправляет нежелательные сообщения.
- [ ] Согласия/удаление/стоп-функции протестированы.
- [ ] Обработка исключений Telegram `429` с учётом `retry_after`.
