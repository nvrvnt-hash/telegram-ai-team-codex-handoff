# Пошаговый план для Codex

Правило: **один этап за один диалог/команду**, отчёт и подтверждение владельца между этапами. На каждом этапе действует `TOKEN-ECONOMY.md`; не перечитывать весь проект. Официальный Caveman — опционален.

| Этап | Задача | Основной контроль |
|---|---|---|
| 00 | Read-only аудит имеющегося кода и зависимостей | Никаких изменений исполняемого кода; план рисков и LLM token baseline |
| 01 | Надёжное локальное окружение Windows 11, config и тесты | Offline tests зелёные, инструкции воспроизводимы |
| 02 | RBAC: admin vs public, согласие и команды управления данными | Публичные пользователи не вызывают приватные роли |
| 03 | Управляющий и устойчивое делегирование | Схема плана, тесты отказов, число LLM вызовов, бюджетные и token limits |
| 04 | Личные Telegram-диалоги | Реальные DM smoke tests по чек-листу, после ручной настройки |
| 05 | Только разрешённые группы | @mention/reply/команды, тишина при отсутствии вызова, нет утечек |
| 06 | Приёмка, мониторинг, безопасный локальный запуск | Полный checklist, измеренные usage, сравнение качества/расходов, аварийная остановка |

Дополнительно, **после отдельного решения**, а не в рамках этих этапов: верифицированная товарная база знаний, n8n/CRM, автономные долгие задания, визуальная генерация и web search. Их нельзя считать уже подключёнными.

## Отчёт после каждого этапа
1. Сделанные изменения и пути файлов.
2. Выполненные команды и точный вывод тестов.
3. Проверенные сценарии vs неподтверждённые интеграции.
4. Известные риски и конфликты.
5. Как повторить тест на Windows.
6. Что будет в следующем этапе и какое решение требуется.
