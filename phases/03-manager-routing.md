# Этап 03 — управляющий и несколько специалистов

**Цель:** надёжный маршрут request → manager plan → 1–3 roles → answer.

Уточнить и проверить:
- строгая схема планирования, допустимые роли и проверка подзадач;
- роль выбирается только после проверки прав; Manager не может обойти эти ограничения;
- фиксированное число одновременно вызываемых ролей и модельных запросов;
- сбой одной роли/общий таймаут даёт понятный частичный или отказной ответ без выдуманных выполненных действий;
- отдельные prompts по ролям и сводка на подтверждённых фактах;
- лимит расхода на пользователя/группу/сутки и механизм остановки (использовать измеримые API usage при наличии; fallback лимит запросов без фальшивых денежных оценок);
- тесты с FakeLLM включая ошибки, противоречивые ответы, неизвестную роль, пустой план;
- в журнале хранить только ограниченные метаданные и statuses без сырых промптов.

**Приёмка:** воспроизводимые тесты типовых сценариев, ошибок и затрат; отсутствуют непредусмотренные side effects. **Остановиться.**

## Token budget (обязательно)
Реализовать и протестировать требования `docs/runtime-cost-design.md`: 0 LLM на статические команды; по возможности 1 вызов на простой запрос; fan-out не выше конфигурации; учёт реального usage; отказ при исчерпании лимита без новых вызовов; отсутствие общего кэша приватного контента. Сопоставить качество результата до/после.
