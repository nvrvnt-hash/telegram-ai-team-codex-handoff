# Фактическое состояние кодовой базы на момент передачи

Дата: 30 октября 2026. Основа: `telegram-ai-team-v0.1.0` из предыдущей подготовки.

## Проверено локально при сборке (без секретов)
- `python -m pytest tests -q`: **5 passed** на среде сборки.
- Исходный код `app/`, `tests/`, `requirements.txt`, `Dockerfile`, `docker-compose.yml`, `.env.example` скопирован без модификаций.
- Реальный запуск через Telegram Bot API **не проверялся**; OpenAI API **не вызывался**.

## Что реально реализовано
- Маршрутизация менеджером на 1–3 роли + параллельная обработка и сводка;
- 7 роли с независимыми role prompts;
- aiogram polling, private chat, allowlist групп, упоминания/reply/команды;
- rate limit на пользователя (в памяти), общий semaphore;
- короткий приватный контекст в памяти и SQLite-журнал метаданных;
- команда удаления журнала и короткой памяти.

## Критичные места для аудита Codex
1. **Нет ADMIN_USER_IDS / RBAC:** любой человек, написавший в личку, сейчас потенциально может вызвать все роли. Прежде чем подсоединять внутренние источники, строго разделить приватный и публичный контуры.
2. **Нет полноценного consent/stop/privacy/human:** минимальный help сейчас не заменяет явную политику и управление доступом.
3. **Нет лимитов суточного бюджета, global/user quotas, circuit breaker, дедупликации Telegram update_id, устойчивых таймаутов ответа.** Не считать это готовым публичным продакшеном.
4. **Нет проверенной товарной базы, CRM, n8n, визуальных инструментов, веб-поиска для research.** Специалисты сейчас пишут текст, а не исполняют внешние инструменты.
5. Тесты охватывают базовый оркестратор, security-helpers, журнал и контекст; нет сквозных тестов обработчиков, режимов доступа, отказов API и consent.
6. Журнал задач хранит ID чата и пользователя; необходимо определить доступ, сроки хранения и удаление в соответствии с целью обработки.
7. Текущий `README` перенесён в `docs/original/README-MVP-0.1.0.md` для сверки; новые файлы передачи не являются доказательством внедрения.

**Решение:** первым делом read-only аудит, затем защита прав и только потом ручное подключение ключей/реальный запуск.
